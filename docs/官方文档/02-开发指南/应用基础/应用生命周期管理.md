# 应用生命周期管理
> 原文链接: https://webostv.developer.lge.com/develop/guides/app-lifecycle-management ｜ 简体中文翻译

基于应用的生命周期，当系统或用户触发相关事件时，你的应用需要管理其自身状态。本节简要介绍应用的各个状态之间如何转换，以及是什么导致了这些转换的发生。

## 启动应用

Web 应用由 Application Manager 服务（`**com.webos.applicationManager**`）启动。Application Manager 服务可由以下任一方式调用：

-   Launcher（启动器）
-   任意 webOS TV 应用
-   运行在 webOS TV 上的 webOS TV 服务或自定义 JavaScript 服务
-   CLI 命令 `**ares-launch**`
-   模拟器上的 App Manager

## 处理应用启动

webOS TV 会触发 `**webOSLaunch**` 事件来启动一个应用。`**webOSLaunch**` 事件由以下任一方式触发：

-   点击应用图标
-   CLI 命令 `**ares-launch**`
-   调用 Luna Service API 上 Application Manager 的 `**launch()**` 方法
-   在模拟器上的 App Manager 中点击 **LAUNCH**（启动）

当 `**webOSLaunch**` 事件被触发时，应用被启动并运行在前台。

## 处理应用重新启动

如果应用在已经运行时又收到了 `**webOSLaunch**` 或 `**visibilityChange**` 事件，webOS TV 会触发 `**webOSRelaunch**` 事件，而不是从头开始启动流程，以避免不必要的开销。

`**webOSRelaunch**` 事件可由以下任一方式触发：

-   使用 CLI 命令 `**ares-launch**`
-   调用 Luna Service API 上 Application Manager 的 `**launch()**` 方法
-   在模拟器上的 App Manager 中点击 **LAUNCH**（启动）

在 [appinfo.json](../../03-API参考/配置文件/appinfo.json应用元数据.md) 文件中有一个名为 `**handlesRelaunch**` 的属性（该文件包含应用的元数据），用于定义应用是否自行处理 `**webOSRelaunch**` 事件。借助该属性，你可以让应用在重新被启动到前台之前，在后台执行一些操作。当需要重新启动应用时，无论 `**handlesRelaunch**` 属性的值如何，webOS TV 都会触发 `**webOSRelaunch**` 事件，但根据该属性值的不同，你的应用的下一步动作也会有所不同。

如果应用的 `**handlesRelaunch**` 属性设置为：

-   **`false`**，则应用不会自行处理重新启动和启动参数。这意味着，当 `**webOSRelaunch**` 事件发生时，webOS TV 会立即在前台以全屏模式显示该应用。
-   **`true`**，则应用会在前台可见之前，在后台以某种方式处理 `**webOSRelaunch**` 事件。在调用 `**PalmSystem.activate()**` 之后，webOS TV 会在前台以全屏模式显示该应用。

![handlesRelaunch 属性示意图——根据属性值对比相应行为的图片](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1649914919/webOS-TV/images/docs/guides/Develop_handlesRelaunch_swe6u8.png)

> **注意（Note）**
>
> 在 webOS TV 4.x 或更低版本中，仅支持 `**PalmSystem**`；而在 webOS TV 5.0 或更高版本中，同时支持 `**PalmSystem**` 和 `**webOSSystem**`。尽管 `**PalmSystem**` 出于向后兼容性仍受支持，但未来的支持并不被保证，因此强烈建议你在 webOS TV 5.0 或更高版本中使用 `**webOSSystem**`。

处理 `**webOSRelaunch**` 事件的应用示例包括：

-   一个浏览器收到带有 URL 参数的 `**webOSRelaunch**` 事件，并在新标签页中打开该 URL。
-   一个下载客户端收到带有文件名参数的 `**webOSRelaunch**` 事件，并将该文件添加到其下载队列中。
-   一个收到 `**webOSRelaunch**` 事件并为其自身应用内设置启动相应 UI 的应用。

## 添加事件监听器

应用可以拥有一个事件监听器来处理 `**webOSLaunch**` 或 `**webOSRelaunch**` 事件。当指定的事件发生时，事件监听器会收到通知并处理该事件。此外，已添加的事件监听器会收到一个包含启动参数的事件参数。

```javascript
// webOSLaunch 事件
document.addEventListener('webOSLaunch', function(inData) {
    // 检查接收到的参数
    console.log(JSON.stringify(inData.detail));

    // 在前台做一些操作
    ...
}, true);

// webOSRelaunch 事件
document.addEventListener('webOSRelaunch', function(inData) {
    // 检查接收到的参数
    console.log(JSON.stringify(inData.detail);

    // 在后台做一些操作
    ...

    PalmSystem.activate();

    // 在前台做一些操作
    ...
}, true);
```

## 管理应用可见性

应用启动后，根据用户交互和系统事件的不同，它可能是可见的，也可能是隐藏的。当已启动的应用收到 `**visibilityChange**`（隐藏）事件时，其状态变为挂起（suspended），其可见性变为隐藏。

应用可见性可通过以下任一操作变为隐藏：

-   当前应用启动了另一个应用。
-   从 App Manager 中选择了另一个应用。

另一方面，可见性可通过以下任一操作变为可见：

-   点击应用图标。
-   在"最近使用"（Recents）中选择该应用。

当应用的可见性在可见与隐藏之间切换时，会触发 `**visibilityChange**` 事件，webOS TV 会向应用发送 `**onwebkitvisibilitychange**` 事件。应用可以拥有一个事件监听器，以便在其可见性发生变化时采取相应动作。

下面的示例代码演示了如何添加事件处理器。

```javascript
document.addEventListener(
  'visibilitychange',
  function () {
    if (document.hidden) doHiddenCleanup();
    else doShowingTasks();
  },
  true
);
```

下一个示例代码演示了如何为各种标准 Web 引擎添加事件处理器。出于向后兼容性考虑，建议你为标准 Web 引擎添加事件监听器。

```javascript
var hidden, visibilityChange;

if (typeof document.hidden !== 'undefined') {
  // 用于支持标准 Web 浏览器引擎
  hidden = 'hidden';
  visibilityChange = 'visibilitychange';
} else if (typeof document.webkitHidden !== 'undefined') {
  // 用于支持 webkit 引擎
  hidden = 'webkitHidden';
  visibilityChange = 'webkitvisibilitychange';
}

document.addEventListener(
  visibilityChange,
  function () {
    if (document[hidden]) doHiddenCleanup();
    else doShowingTasks();
  },
  true
);
```

## 终止应用

处于已启动或挂起状态的应用可通过以下任一方式被终止：

-   点击系统 UI 上的 **X**（关闭）按钮
    应用不允许拥有自己的关闭按钮，因此用户应点击 **X**（关闭）按钮来终止应用。参见 **System UI（系统 UI）** 下的 [Closing apps（关闭应用）](https://webostv.developer.lge.com/develop/guides/interacting-with-apps)。
-   CLI 命令 `**ares-launch --close**`
-   在模拟器上的 App Manager 中点击 **TERMINATE**（终止）
