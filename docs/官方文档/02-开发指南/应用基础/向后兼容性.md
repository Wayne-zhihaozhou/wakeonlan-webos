# 向后兼容性（Backward Compatibility）
> 原文链接: https://webostv.developer.lge.com/develop/guides/backward-compatibility ｜ 简体中文翻译

我们一直在不断改进 webOS TV，因此各种规范（specifications）和功能被新增或更改到 webOS TV 平台中。例如，webOS TV 平台中使用的 Web 引擎在 webOS TV 3.0 发布时从 [WebKit](https://webkit.org/) 改为了 [Blink](http://www.chromium.org/blink)。由于此类更改，你为之前 webOS TV 版本制作的 app 可能无法在最新版 webOS TV 上运行。现在是时候考虑向后兼容性了。

下面的指南描述了因版本差异而产生的问题，以及如何让代码在所有版本的 webOS TV 上都能正常工作。

## 添加事件处理器（Adding event handler）

| 相关规范 | 主要原因 | 适用范围 |
| --- | --- | --- |
| [addEventListener](https://www.w3.org/TR/domcore/#dom-eventtarget-addeventlistener)、HTMLMediaElement | [Web 引擎](../../04-平台规格/Web平台/WebAPI与Web引擎.md#web-engine) 变更 | webOS TV 2.0 及更早版本 |

### 向后兼容的代码

添加事件处理器时，你**必须**使用 `**addEventListener()\`** 方法，才能使代码在所有版本的 webOS TV 上正常工作：

```javascript
var vid = document.getElementById("myVideo");

vid.addEventListener("loadeddata", function (event) {
    log(JSON.stringify(event));
});

<!-- HTML Code -->
...
<video id="myVideo">
    <source src="./video/oceans-clip.mp4" type="video/mp4" />
</video>
```

### 为什么要使用这段代码？

在 webOS TV 1.x 和 2.0 中，当 HTMLMediaElement 的事件发生时，只有通过 `**addEventListener()\`** 方法注册的事件处理器才能被调用。如下所示，如果你以属性（property）形式添加事件处理器，它将无法正常工作。

```javascript
// JavaScript Code
var vid = document.getElementById("myVideo");

vid.onloadeddata = function (event) {
    log(JSON.stringify(event));
});
```

```html
<!-- HTML Code -->
...
<video id="myVideo">
  <source src="./video/oceans-clip.mp4" type="video/mp4" />
</video>
```

## 使用 CSS

| 相关规范 | 主要原因 | 适用范围 |
| --- | --- | --- |
| [CR 状态的 CSS 模块](../../04-平台规格/Web平台/WebAPI与Web引擎.md#supported-web-api)、CSS | [Web 引擎](../../04-平台规格/Web平台/WebAPI与Web引擎.md#web-engine) 变更 | webOS TV 2.0 及更早版本 |

### 一段适用于所有版本的代码

为确保你的 app 兼容所有版本的 webOS TV，请在 CSS 代码中同时写入带前缀和不带前缀的标记，如下所示：

```css
div {
  -webkit-animation-duration: 4s;
  animation-duration: 4s;
  -webkit-animation-name: myMove;
  animation-name: myMove;
}

@-webkit-keyframes myMove {
  /* styles */
}
@keyframes myMove {
  /* styles */
}

.item {
  display: -webkit-flex;
  display: flex;
  -webkit-justify-content: flex-end;
  -webkit-align-items: flex-end;
  justify-content: flex-end;
  align-items: flex-end;
}
```

### 为什么要使用这段代码？

如果你按照最新的 W3C 指南使用了下面这段 CSS 代码，你很可能会发现它在 webOS TV 2.0 或更早版本上无法正常工作：

```css
div {
  animation-duration: 4s;
  animation-name: myMove;
}

@keyframes myMove {
  /* styles */
}

.item {
  display: flex;
  justify-content: flex-end;
  align-items: flex-end;
}
```

在 webOS TV 3.0 之前，包括 Transforms、Transitions 和 Animation 在内的一些 CSS 模块处于「候选推荐（Candidate Recommendation，CR）」状态。当时，官方建议使用前缀（例如 webkit-xxx）来实现这些 CSS 模块。然而，随着这些模块在推荐标准（recommendation track）中的成熟度提升，W3C 更新了相关文档，并建议去除厂商前缀（vender prefix，这是 Blink 的标准做法）。为了应对这一变化，你需要编写一种能在所有 webOS TV 版本上工作的代码。请参见页面顶部的示例代码。

## 更改视频源（Changing video source）

| 相关规范 | 主要原因 | 适用范围 |
| --- | --- | --- |
| [readyState](https://www.w3.org/TR/html5/embedded-content-0.html#ready-states)、HTMLMediaElement | [Web 引擎](../../04-平台规格/Web平台/WebAPI与Web引擎.md#web-engine) 变更 | webOS TV 3.0 及更新版本 |

### 向后兼容的代码

在更改 source 元素之前，你需要考虑 readyState 的状态。我们建议使用 `**load()\`** 方法来初始化 readyState，如下所示：

```javascript
// JavaScript Code
function changeSource() {
  var vidElement = document.getElementById('myVideo');

  // Remove all source elements
  while (vidElement.firstChild) vidElement.removeChild(vidElement.firstChild);

  // Initiating readyState of HTMLMediaElement
  vidElement.load();

  // Add new source element
  var source = document.createElement('source');
  source.setAttribute('src', './video/multi-soundtrack.mp4');
  source.setAttribute('type', 'video/mp4');
  vidElement.appendChild(source);
}
```

```html
<!-- HTML Code -->
...
<video id="myVideo">
  <source src="./video/oceans-clip.mp4" type="video/mp4" />
</video>
```

### 为什么要使用这段代码？

source 元素用于播放 MPEG、HLS 和 DRM 格式的内容。根据 HTML5 规范，如果 [HTMLMediaElement 的 readyState](https://www.w3.org/TR/html5/embedded-content-0.html#ready-states) 不是 HAVE\_NOTHING，则无法更改或移除 source 元素。在视频播放期间，readyState 通常会被设置为 HAVE\_NOTHING 以外的值。然而，webOS TV 1.x 和 2.0 上使用的 [WebKit](https://webkit.org/) 不支持 readyState，并且[将 readyState 的值保持为 HAVE\_NOTHING（NULL）](https://codereview.chromium.org/349973006)。随着 webOS TV 3.0 的发布，WebKit 被 [Blink](http://www.chromium.org/blink) 取代，而 Blink 完全支持 readyState。

你可能曾通过替换 source 元素来更改视频内容，做法与下面类似。然而，自 webOS TV 3.0 起，这段代码已经无法正常工作了。

```javascript
// JavaScript Code
function changeSource() {
  var vidElement = document.getElementById('myVideo');

  // Remove all source elements
  while (vidElement.firstChild) vidElement.removeChild(element.firstChild);

  // Add a new source element
  var source = document.createElement('source');
  source.setAttribute('src', './video/multi-soundtrack.mp4');
  source.setAttribute('type', 'video/mp4');
  vidElement.appendChild(source);
}
```

```html
<!-- HTML Code -->
...
<video id="myVideo">
  <source src="./video/oceans-clip.mp4" type="video/mp4" />
</video>
```
