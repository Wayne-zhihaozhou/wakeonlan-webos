# 动作传感器的传感器数据
> 原文链接: https://webostv.developer.lge.com/develop/guides/motion-sensor-sensor-data ｜ 简体中文翻译

Motion Sensor API（动作传感器 API）处理来自 Magic Remote（魔法遥控器）的数据，并向宿主系统提供多种输出。

## 参考坐标系

webOS TV Motion Sensor API 处理动作时基于一个参考坐标系。该设备的参考坐标系表示为：X 轴为水平方向，向右为正；Y 轴为垂直方向，沿魔法遥控器顶部点的方向为正；Z 轴从魔法遥控器正面朝外为正。

参考坐标系如下图所示。

![动作传感器参考坐标系](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1708329039/webOS-TV/images/docs/guides/Motion_sensor_reference_frame_l8lyk5.png)

## 光标输出

Motion Sensor API 以魔法遥控器经过校准的角速度与姿态作为输入，并将角速度映射到用户所感知的、投影屏幕的 X 轴与 Y 轴所在坐标系上。

这些数据定义了屏幕上像素值的绝对位置，即 x（水平）与 y（垂直）。

```javascript
int x
int y
```

## 动作输出

### 加速度

三轴加速度计测量魔法遥控器的加速度。请注意，加速度计会将重力也作为加速度进行测量。Motion Sensor API 会对加速度计数据进行校准以改善动作输出，并报告与魔法遥控器坐标系对齐的加速度。

在与陀螺仪数据进行融合后，Motion Sensor API 会从加速度中分离出重力，并提供以下加速度输出：

```javascript
//魔法遥控器的加速度（含重力，单位：m/s2）。
double accelerometer.x,y,z 
//魔法遥控器未经校准的加速度（含重力，单位：m/s2），以及估算的加速度计偏差（单位：m/s2）。
double accelerometer.x_uncalibrated, y_uncalibrated, z_uncalibrated, x_bias, y_bias, z_bias 
//加速度中的重力部分（单位：m/s2），需要与陀螺仪进行传感器融合。
double gravity.x, y, z 
//去除重力后魔法遥控器的加速度（单位：m/s2）。
double linearAcceleration.x, y, z
```

### 角速度

三轴陀螺仪测量魔法遥控器的角速度。角速度以绕 X、Y、Z 轴的旋转来报告，如[参考坐标系](#参考坐标系)一节的图示所示。

逆时针旋转会报告为正值。Motion Sensor API 会对陀螺仪数据进行校准以提高准确性，并提供以下输出：

```javascript
// 魔法遥控器的角速度（单位：rad/s）。
double gyroscope.x,y,z
// 魔法遥控器未经校准的角速度（单位：rad/s），以及估算的陀螺仪偏差（单位：rad/s）。
double gyroscopeUncalibrated.x_uncalibrated, y_uncalibrated, z_uncalibrated, x_bias, y_bias, z_bias
```

![动作传感器角速度](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1708329038/webOS-TV/images/docs/guides/Motion_sensor_angular_velocity_efxdzv.png)

### 姿态

通过融合加速度计与陀螺仪的数据，Motion Sensor API 提供对魔法遥控器姿态的估算。

```javascript
double gameRotationVector.x,y,z,w
```

game rotation vector（游戏旋转矢量）是一种姿态输出，以四元数（quaternion）表示，其航向（heading）没有特定参考，而横滚（roll）与俯仰（pitch）则以重力为参考。当没有磁力计可用于修正偏航（yaw）方向的陀螺仪漂移时，会使用 game rotation vector。这是按照 Android 规范有意省略的，旨在让游戏应用能够使用更平滑的姿态表示，而不会因磁场更新导致的瞬时修正而产生跳变。

从长期来看，由于陀螺仪本身的特性，该输出在偏航方向可能会出现漂移，但与使用磁力计进行修正后的输出相比，对于此输出而言这种做法被视为更优。

![动作传感器姿态输出](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1708329035/webOS-TV/images/docs/guides/Motion_sensor_orientation_output_flqgnu.png)

通过融合加速度计与陀螺仪的数据，Motion Sensor API 提供对魔法遥控器姿态的估算。

```javascript
double gameRotationVector.euler.pitch, roll, yaw
```

四元数也可以在转换为欧拉角（Euler angles）后提供。对于旋转的表达而言，通过欧拉角来实现较为简便，但由于转换并不容易，因此将其单独提供。

![动作传感器姿态输出（欧拉角）](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1708329035/webOS-TV/images/docs/guides/Motion_sensor_orientation_output_Euler_angle_jkorm7.png)![动作传感器姿态输出（欧拉角 II）](https://res.cloudinary.com/dcsdn4mzr/image/upload/f_auto/q_auto/v1708329034/webOS-TV/images/docs/guides/Motion_sensor_orientation_output_Euler_angleII_aeafej.png)

### 分类

#### 显著动作检测器

```javascript
int significantMotion
```

当用户做出暗示位置发生变化的动作时，应触发一个事件。一个典型的用例是：传感器的功耗很低（因为它可以在设备休眠时运行），当预计位置会发生变化时，它会向魔法遥控器的主处理单元发出提醒。

Motion Sensor API 使用步数检测器（step detector）及其基于加速度计的处理，来判断用户是否做出了显著动作。当检测到动作时，检测器会输出 1.0 的值，并在事件输出后立即自行复位。例如，在行走过程中，检测器事件大约每五步报告一次。

显著动作检测器的配置包括：

-   **显著动作步数阈值（Significant motion step threshold）**：触发事件所需的步数。默认值为 5 步。
-   **加速度阈值（Acceleration threshold）**：一个大致基于设备加速度、用于触发显著动作处理的阈值。默认值为 10m/s²。

#### 步数检测器

```javascript
int stepDetected
```

步数检测器使用加速度计的数据来检测步伐。每当检测到一步时，它都会输出 1.0 的值。步数检测器的配置包括：

-   **`allowTime`**：步频周期的最大变化量，180ms。
-   **`stepMinTime`**：最小步频周期，300ms。
-   **`groupDelay`**：滤波器的群延迟。需要对加速度计数据进行滤波，以确保准确检测步伐，尤其是在加速度计相对重力旋转时。滤波器的群延迟是响应性与误差累积之间的折衷。采用 90ms 的值。
-   **`threshold`**：以米为单位的垂直运动阈值。如果垂直运动小于此阈值，则不会被识别为一步。其值为 3.1mm。

#### 计步器

```javascript
int stepCount
```

它计算系统启动后的步数。计步器使用步数检测器来检测和统计步数。与步数检测器相比，它能提供关于所行走步数更准确的数据。通过评估每个步事件周围的数据，它提高了计数精度，并且还可能会根据所感知到的模式，将先前的样本重新分类为步或非步。

#### 计步器

```javascript
int stepDetectedLatency
//过去曾检测到步峰值的样本数量。
//当 stepDetected=1 时有效
```

通常这些信息会由传感器事件时间戳来提供，但由于该接口不提供时间戳，如果需要，可以使用此值来调整 **`stepDetected`** 与 **`stepCount`** 事件的应用时间戳。

**注意**
