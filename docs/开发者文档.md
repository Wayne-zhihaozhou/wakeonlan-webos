## 1. 技术栈与平台

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML / CSS / JavaScript（ES5） | 无框架，单页应用，`PalmServiceBridge` 调 Luna 服务 |
| 后台服务 | Node.js + `webos-service` | 常驻 Luna 服务，运行在电视端 |
| 存储 | DB8（`com.palm.db`） | 保存目标 MAC / IP / 端口配置 |
| 系统服务 | `connectionmanager` / `tvpower` / `activitymanager` | 网络就绪检测、开机事件订阅、常驻保活 |
| 打包部署 | @webos-tools/cli（`ares-*`）+ PowerShell | 打包 .ipk、安装、启动 |

前端代码刻意写成 ES5（var + 立即执行函数），以兼容 webOS 内置浏览器环境。

## 3. 整体架构

```
 ┌─────────────── 电视端 ───────────────┐
 │                                      │
 │  Web 应用 (index.html + js/app.js)   │
 │   └─ PalmServiceBridge ────────────┐ │
 │                                    ▼ │
 │   Luna 服务 com.woltv.wakeonlan.service (wol_service.js, 常驻)   │
 │   ├─ service.call   → com.palm.db              (DB8: 读写配置)   │
 │   ├─ service.call   → connectionmanager       (网络就绪检测)    │
 │   ├─ service.subscribe → tvpower/power/*      (开机/恢复事件)    │
 │   └─ service.activityManager.create → activitymanager (常驻保活) │
 │                                    │
 │                                    ▼
 │                        dgram 发送 UDP 魔术包 → 局域网电脑
 └──────────────────────────────────────┘
```

关键点：

- **前端与后台解耦**：前端只通过 Luna 方法名调用，不直接碰 UDP / 数据库。
- **后台常驻**：JS 服务默认按需拉起、空闲 5 秒即退出（`webos-service` 的 `activitymanager.js` idleTimer）。本项目用 `service.activityManager.create('wol-resident', cb)` 创建一个 JS 侧占位 Activity，永久停掉 idle 计时器，从而让服务常驻，保证能长期持有 tvpower 订阅。详情见 [探索记录](../docs/探索经验/快速启动开机唤醒-探索记录.md) §6。

## 4. Luna 服务 API（`luna://com.woltv.wakeonlan.service`）

前端统一通过 `js/app.js` 中的 `callService(method, params, timeoutMs)` 调用，内部用 `new PalmServiceBridge()`，超时默认 12 秒。

### 4.1 命令方法（由 `service.register` 注册，均在 `services.json` 中声明为 `public`）

| 方法 | 参数 | 返回（returnValue 为 true 时） | 说明 |
|---|---|---|---|
| `getConfig` | `{}` | `{ config: { mac, ip, port, broadcast, _id } }` | 读取当前配置（读 DB8） |
| `setConfig` | `{ mac, ip, port }` | `{ config: {...} }` | 保存配置到 DB8；`mac` 必填 |
| `wake` | `{ mac?, ip?, port?, reason? }` | `{ sent: true }` | 立即发送一次魔术包（缺省用已存配置） |
| `getStatus` | `{}` | 见 §7 | 返回常驻 / 订阅 / 事件 / 最近发送等诊断状态 |
| `scan` | `{}` | `{ devices: [{ip, mac, device}], broadcast, localIp }` | 扫描局域网在线设备，最长约 45 秒 |

### 4.2 回调 / 订阅方法（`services.json` 中声明，供系统回调）

| 方法 | 方向 | 说明 |
|---|---|---|
| `registerPreparePowerOn` | 系统→服务 | 收到后应答并触发 `powerOn` 唤醒 |
| `preparePowerOn` | 系统→服务 | 同上（非注册版入口） |
| `registerPrepareResume` | 系统→服务 | 收到后应答并触发 `resume` 唤醒 |
| `prepareResume` | 系统→服务 | 同上 |

这些方法同时通过 `service.subscribe`（主动订阅 tvpower）和 `service.register`（被动接收回调）两种方式接入，双保险。

## 5. 开机自动唤醒机制（核心）

目标：电视开机或从待机恢复时，自动向目标电脑发送一次魔术包。需要同时覆盖两种场景（详见 [探索记录](../docs/探索经验/快速启动开机唤醒-探索记录.md)）：

| 场景 | 触发来源 | 说明 |
|---|---|---|
| 冷启动 | ActivityManager `persist` Activity | 冷启动时系统回调 `luna://…/wake`（reason=boot），把服务拉起并发送 |
| 快速启动+恢复 | tvpowerd `preparePowerOn` 订阅 | 服务常驻持有订阅，收到开机事件后应答并发送 |

### 5.1 冷启动链路（`ensurePersistActivity`）

通过 `com.palm.activitymanager/create` 创建一个 `type: { persist: true, background: true }` 的 Activity，`callback.method` 指向本服务的 `/wake`（params `reason=boot`）。冷启动时系统执行该 Activity，跨冷启拉起服务并发送魔术包。

### 5.2 快速启动+链路（`registerPowerTriggers` / `registerIncomingHooks`）

- 用 **v1 `power/*` 路径**（`power2/*` 对普通应用会 Denied）：`service.subscribe(TVPOWER_URI + '/' + trigger.method, { clientName, subscribe: true })`。
- 收到事件后必须**应答**：`service.call(tvpower, 'responsePreparePowerOn', { clientName, ack: true, timestamp })`。`timestamp` 必须原样回传事件里的值，应答窗口很短。
- 事件负载示例：
  ```json
  {"returnValue":true,"timestamp":"3367540976","onOff":"on","reason":"remoteKey",
   "state":"Active Standby","instantBoot":"on"}
  ```
  `state: Active Standby` + `instantBoot: on` 即为「快速启动+」场景。

### 5.3 发送前等网络就绪（`sendWOLWhenNetworkReady`）

电视刚开机时网络可能未就绪。发送前轮询 `connectionmanager/getStatus`，直到判定已联网（`isConnectedPayload` 检查 `connected` / `wired` / `wifi` / `state` 等字段），或 5 分钟超时。随后**只发送一次**魔术包。

### 5.4 魔术包构造（`buildMagicPacket`）

标准格式：6 字节 `0xFF` + 目标 MAC 重复 16 次，共 102 字节，经 UDP 发出。默认目标 `255.255.255.255:9` 广播（`FLAGS.broadcast = true` 时 `socket.setBroadcast(true)`）。

### 5.5 兜底与保护

| 机制 | 实现 | 目的 |
|---|---|---|
| 时钟跳变兜底 | 10 秒心跳，两次间隔 > 60 秒则判定为「刚从待机恢复」并发送 | 防止订阅丢失 / 进程被冻结漏触发 |
| 30 秒去重 | `triggerWake` 内判断与上次触发间隔 | 避免事件与兜底重复发送 |
| 60 秒重注册 | 定时检查 `power.triggers[*].subscribed`，非 subscribed 时重订阅 | 订阅丢失自愈 |
| 订阅 cancel 重连 | `subscription.on('cancel')` 后 5 秒重新注册 | 断线重连 |

## 6. 数据存储（DB8）

- Kind：`com.woltv.wakeonlan:1`（owner 为服务本身，`private: true`，含 `default` 索引）。
- 配置字段：`_id`、`_kind`、`mac`、`ip`、`port`。
- 读写流程：`loadConfig` 首次 `find` 后缓存到内存 `configCache`，后续直接读缓存；`saveConfig` 用 `put` 写入，失败时先 `putKind` 建 kind 再重试。
- 默认配置（无记录时）：`mac` 见 `wol_service.js` 的 `DEFAULT_CONFIG`，`ip: 255.255.255.255`，`port: 9`。

## 7. 状态自诊断（`getStatus`）

前端「开机触发状态」卡片每 5 秒拉取一次，用于排查「有没有注册上 / 发没发出去」：

```json
{
  "returnValue": true,
  "lastSend":  { "at": 0, "ok": false, "error": "", "reason": "" },
  "startedAt": 1700000000000,
  "uptimeSec": 1234,
  "resident":  { "ok": true, "activityId": "..." },
  "heartbeat": { "last": 0, "gapCount": 0, "lastGapMs": 0 },
  "power": {
    "eventCount": 3,
    "lastEvent": { "reason": "powerOn", "at": 0, "detail": {} },
    "events": ["..."],
    "triggers": { "registerPreparePowerOn": { "subscribed": true, "events": 0 } }
  }
}
```

排查要点（详见 [探索记录](../docs/探索经验/快速启动开机唤醒-探索记录.md) §9）：

- `resident.ok` → 服务是否常驻。
- `power.triggers.registerPreparePowerOn.subscribed` → 开机通知是否注册成功。
- `power.eventCount` / `power.events` → 收到的开机事件。
- `heartbeat.gapCount` → 时钟跳变兜底触发次数。
- `uptimeSec` → 服务实例存活时长（跨待机不重启 = 常驻生效）。

## 8. 构建与部署

### 8.1 环境

- Node.js + `npm install -g @webos-tools/cli`（提供 `ares-package` / `ares-install` / `ares-launch` / `ares-config` / `ares-novacom`）。
- 电视开启开发者模式，记录 Passphrase。

### 8.2 一键部署脚本 `deploy-wakeonlan.ps1`

`pwsh` 下运行（或 PowerShell 5.1，需脚本为 UTF-8 with BOM）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-wakeonlan.ps1
```

可选参数：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-TvIp` | `192.168.1.4` | 电视 IP |
| `-TvPort` | `9922` | 电视 SSH / Novacom 端口 |
| `-Device` | `lg` | ares 设备配置名 |
| `-Passphrase` | — | 6 位口令（否则读环境变量 / passphrase.txt / 交互输入） |
| `-ProjectDir` | 脚本目录 | 项目根目录 |
| `-SkipLaunch` | 关 | 部署后不自动启动应用 |
| `-TestWake` | 关 | 部署后尝试触发一次唤醒（依赖 `ares-shell`，`tv` profile 下无效，见下） |
| `-NoPause` | 关 | 结尾不暂停（供 CI） |

流程 8 步：检查 ares → 设 profile=tv → 定位本地网卡并直连测试 → 启动中继 + 指向 ares → 取 SSH 密钥 → 验证连接 → 打包 → 安装。

> ⚠️ `-TestWake` 依赖 `ares-shell`，在 `profile=tv` 下会报 `This command is not supported by current profile`。要触发服务，用 `luna-send-pub`（见 [电视 SSH 调试指南](../docs/探索经验/电视SSH调试指南.md) §5.3）。

### 8.3 本地中继绕开 VPN

`deploy-wakeonlan.ps1` 与 `tools/tv-shell.ps1` 都内置了一个「本地 TCP 中继」：只监听 `127.0.0.1`，出站连接前 `Bind()` 到本地物理网卡 IP，从而强制走该网卡、绕过路由表。这是为了规避公司 VPN（如 SecoClient）与家庭网段冲突导致的「连不到电视」问题。原理与实现见 [TROUBLESHOOTING.md](../docs/探索经验/TROUBLESHOOTING.md) §5。

- 部署脚本会临时改写 `%APPDATA%\.webos\tv\novacom-devices.json` 的 host/port 指向中继，`finally` / `trap` 中幂等还原（备份 `.wolbak`）。
- 被强杀时需人工检查该配置是否已还原。

### 8.4 注入 buildHash

打包阶段把当前 Git 短哈希写入临时副本的 `appinfo.json` 的 `buildHash` 字段，前端 `loadBuildInfo()` 读取并显示在标题栏。这样电视上显示的就是「当前运行的提交」，用于构建溯源。只改文档不重新打包时，界面仍显示上一次部署的提交哈希。

### 8.5 打包内容

`deploy-wakeonlan.ps1` 会复制 `appinfo.json`、`index.html`、`js/`、`css/`、`icon.png`、`largeIcon.png` 与应用服务目录一起交给 `ares-package`，输出 `dist/*.ipk`。`dist/` 与 `*.ipk` 已在 `.gitignore` 中忽略。

## 10. 开发约定（本项目强制要求）

以下为本项目的内部约定，改动代码时请务必遵守（原 README 中的项目要求，现迁移至此）：

1. **禁止添加代码注释**。修改代码时顺便删除看到的所有注释。
2. **`*.ps1` 保存为 UTF-8 with BOM 编码**（恰好一个 BOM）。无 BOM 的 UTF-8 在 PowerShell 5.1 下会被按 GBK 解码，中文字节偏移会导致**假的语法错误**；双 BOM 会造成第 1 行解析失败。见 [TROUBLESHOOTING.md](../docs/探索经验/TROUBLESHOOTING.md) §6.1/6.2。
3. **界面禁止创建功能开关**。所有功能默认开启、在代码中写死。
4. **提交约定**：每次修改代码后仅提交自己修改过的代码，提交后把该提交的哈希打包到电视应用界面（`deploy-wakeonlan.ps1` 的 `buildHash` 机制）。

### 10.1 修改后如何验证

```powershell
# 校验 ps1 语法（0 个错误才干净）
$errs=$null; $tokens=$null
[System.Management.Automation.Language.Parser]::ParseFile('.\deploy-wakeonlan.ps1',[ref]$tokens,[ref]$errs)
$errs.Count
```

部署后到电视上确认：

```sh
/usr/bin/luna-send-pub -n 1 -f luna://com.woltv.wakeonlan.service/getStatus '{}' < /dev/null
```

## 11. 扩展指南

- **换默认唤醒目标**：改 `wol_service.js` 的 `DEFAULT_CONFIG`（`js/app.js` 里也有一个前端默认 MAC `DEFAULT_MAC`，需同步）。
- **增加 Luna 方法**：在 `wol_service.js` 用 `service.register` 实现，并在 `services.json` 的 `commands` 中声明（需要时设 `public`）。
- **改应用 id**：涉及 `appinfo.json`、`services.json`、服务目录名、服务 `package.json` 的 `name`、`wol_service.js` 的 `SERVICE_NAME`/`KIND`、`js/app.js` 的 `SERVICE`，以及 `deploy-wakeonlan.ps1` 中 4 处引用（详见 [电视SSH调试指南](../docs/探索经验/电视SSH调试指南.md) §7）。
- **图标要求**：平台对图标位深有要求（实测需 **32bpp ARGB**），否则启动器可能仍显示旧图。

---

## 12. 已知限制

- **只能注册、不能查询电源状态**：`power2/*` 与 `getPowerState` 对普通应用会 Denied，方案必须事件驱动（见 [探索记录](../docs/探索经验/快速启动开机唤醒-探索记录.md) §5.1）。
- **`ares-shell` / `ares-pull` / `ares-push` 在 `tv` profile 下不可用**：读电视文件用 SSH 直连。
- **tvpower 内部 API 依赖固件**：电视系统升级或换机后可能变化。回归时先看 `getStatus` 的 `subscribed` 是否为 true，再看日志里有无 `power event`。
